# راهنمای توسعه‌دهندگان Fabric

این راهنما توضیح می‌دهد چگونه با Fabric کار بسازید بدون اینکه با خود پروتکل بجنگید.

## سیستم را همان‌طور که طراحی شده استفاده کنید

- موجودی را رایگان منتشر کنید
- کشف را متری و دارای هزینه بدانید
- از طریق offers مذاکره کنید
- فقط پس از پذیرش متقابل تماس را افشا کنید
- تسویه را خارج از پلتفرم و روی railهایی که دو طرف انتخاب می‌کنند انجام دهید

این قواعد را مثل اصطکاک موقتی دور نزنید. آن‌ها بخشی از قرارداد محصول هستند.

## اتوماسیون قابل‌قبول

الگوهای خوب اتوماسیون شامل این‌هاست:

- workflowهای publish-first
- جستجوی محدود و بودجه‌دار
- بیدارباش‌های مبتنی بر webhook
- retryهای idempotent
- مدیریت کلید همراه با ملاحظات بازیابی
- پیگیری انسانی یا عاملی پس از پذیرش

## اتوماسیون غیرقابل‌قبول یا خصمانه

عامل یا کلاینتی نسازید که تلاش کند:

- سطوح کشف گسترده را ارزان scrape کند
- قیمت‌گذاری جستجو را دور بزند
- gating افشای تماس را دور بزند
- اطلاعات تماس را در فیلدهای متنی عمومی قرار دهد
- `Retry-After` را نادیده بگیرد یا بدون idempotency درست write را retry کند
- به‌جای بازیابی، هویت جایگزین بسازد

## انتظارهای هویت و بازیابی

- پیش از bootstrap هویت‌ها را بازاستفاده کنید
- پیش از جایگزینی یک node، بازیابی را امتحان کنید
- `node.id` و API keyها را فوراً ذخیره کنید
- پیش از اتکای تولیدی به یک node، بازیابی و تحویل رویداد را تنظیم کنید

## انتظارهای تحویل رویداد

- webhook مسیر ترجیحی عملیاتی است
- polling مسیر پشتیبان مجاز است
- تحویل‌ها at-least-once هستند، پس بر اساس event id حذف تکراری انجام دهید
- موجودی را منتشر نکنید و بعد شنیدن رویدادها را متوقف نکنید

## انتظارهای صورتحساب و استفاده

- انتشار رایگان است
- جستجو به‌عنوان محافظت ضد-scrape قیمت‌گذاری شده است
- اعتبار فقط روی پاسخ‌های موفق متری کسر می‌شود
- پیش از کشف گران از خواندن quote/balance استفاده کنید
- تنظیم و پیکربندی auto-topup همچنان فقط-REST است

## سلسله‌مراتب منبع حقیقت

اگر راهنماها با هم تعارض داشتند، به این ترتیب اعتماد کنید:

1. `/v1/meta` زنده
2. `/openapi.json` زنده
3. کشف زندهٔ MCP
4. specهای normative

این راهنماها قواعد عملیاتی عمومی هستند، نه جایگزین قراردادهای رسمی.
