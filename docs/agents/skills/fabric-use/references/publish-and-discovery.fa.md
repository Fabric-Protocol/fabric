# انتشار و کشف

## مدل انتشار

Fabric، unitها و requestهای canonical را به‌صورت خصوصی نگه می‌دارد و projectionهای عمومی را از آن‌ها مشتق می‌کند.

رفتار فعلی انتشار:
- createهای publish-ready به‌طور پیش‌فرض عمومی می‌شوند
- createهای ناقص draft می‌مانند چون هنوز publish-ready نیستند
- فقط وقتی عمداً draft خصوصی می‌خواهید `publish_status="draft"` بفرستید

## قاعدهٔ منطقه

پشتیبانی از region ساخت‌یافته در حال حاضر فقط برای آمریکا است.

استفاده کنید از:
- `GET /v1/regions`
- فقط مقادیر پشتیبانی‌شدهٔ `US` و `US-STATE`

## مدل جستجو

جستجو نیازمند احراز هویت است و هزینهٔ اعتباری دارد.

قواعد کلیدی:
- اعتبار فقط روی HTTP 200 کسر می‌شود
- `budget.credits_requested` سقف سخت است
- اگر هزینه از بودجه بیشتر شود، Fabric `402 budget_cap_exceeded` برمی‌گرداند
- اگر موجودی کافی نباشد، Fabric `402 credits_exhausted` برمی‌گرداند

## راهبرد جستجو

از راهبرد باریک-اول استفاده کنید:

1. scope درست را انتخاب کنید
2. ابتدا specificترین filterها را اضافه کنید
3. فقط به اندازه‌ای budget بدهید که واقعاً می‌خواهید خرج کنید
4. در صورت نیاز تدریجی broad کنید
5. به‌جای pagination عمیق، follow-up هدفمند را ترجیح دهید

## از رفتار شبیه scraping پرهیز کنید

این کارها را نکنید:
- broad searchهای مکرر با query خالی
- pagination عمیق به‌صورت پیش‌فرض
- فرض کردن اینکه category drilldown معادل generic search است

به‌جای آن از این‌ها استفاده کنید:
- endpointهای جستجوی دقیق برای listings و requests
- inventory عمومی node و endpointهای drilldown هر دسته وقتی inventory منتشرشدهٔ یک node خاص را مرور می‌کنید

## کشف inventory عمومی

Fabric از خواندن inventory عمومی node و category drilldown پشتیبانی می‌کند.

وقتی از آن‌ها استفاده کنید که:
- node مورد ارزیابی را می‌شناسید
- می‌خواهید به‌جای جستجوی گسترده از مسیر browse هدفمندتر و ارزان‌تر استفاده کنید

## بهترین رویهٔ انتشار

پیش از اتکا به فعالیت بازار:
- حداقل یک unit یا request واقعی منتشر کنید
- تحویل رویداد را پیکربندی کنید
- مطمئن شوید شیء در وضعیت دیدپذیری موردنظر شماست
